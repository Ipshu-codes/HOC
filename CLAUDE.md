# Ward 16 Heritage Website

- Sites: Mhepi Ajima, Nanak Math — Ward No. 16, Kathmandu Metropolitan City
- Stack: Next.js (App Router) + TypeScript + Tailwind, static export (output: 'export'; devIndicators off so the dev "N" badge doesn't cover the 3D Map button). Hosting: Cloudflare Pages.
- No server features: no API routes, server actions, middleware or ISR.
- Everything must be FREE. No paid services, no API keys needing billing.
- Theme: red. Use only the named Tailwind colors: crimson, brick, vermilion, gold, cream, sand, ink. Vermilion and gold fail AA for body text — decoration / large text only (see src/app/globals.css).
- Layout follows raw-data/sketch.jpg (actual file: ward16-heritageraw-data/HOC/sketch.png).
- Content lives ONLY in content/. Never invent historical facts; use [TODO: …] and log in MISSING_INFO.md.
- Draft content: files with `draft: true` may hold [PLACEHOLDER: …] text. `npm run check-content` (run automatically by `npm run build`) fails on any [PLACEHOLDER, [TODO or draft — never bypass it. In dev, draft pages show <DraftBanner>.
- `npm run build:preview` builds without draft sites. Every page, link, gallery, map marker and chatbot answer must get sites from `getHeritageList()` / `getHeritageSlugs()` (src/lib/content.ts); scripts/verify-output.ts (after both builds) fails if a draft slug or name, or any [PLACEHOLDER/[TODO text, appears anywhere in out/.
- Every h2/h3 in content needs a stable English id, same in EN and NE: `## इतिहास {#history}` (enforced by check-content and the remark plugin).
- Client components import Locale/LOCALES from @/types/locale, never @/types/heritage (that pulls zod and site slugs into the browser bundle).
- People who gave information are credited in one place: content/credits.json → `people` (with an optional `credit` form), and `informationFrom` (site → people ids) adds the "Information from …" line under a heritage page's text (Mhepi Ajima: the chief priest). Content and sources.json write `{person:<id>}` (e.g. `{person:mhepi-priest}`); never type their names into content. An unknown id fails the build; an unfilled token fails verify-output.
- Teamwork rules (branches, PRs, never commit to main, resolving globals.css conflicts by keeping both sides): CONTRIBUTING.md.
- Cite sources in content with `<!-- source: key1, key2 | reviewer detail -->`; keys and their plain-language names live in content/sources.json (an unknown key fails the build). Since 17 Nov 2026 the site shows no Sources section (heritage pages and map panel); the comments stay for reviewers and the build check.
- Placeholder dots ("………", "....", a lone "…" as content) fail check-content and verify-output (scripts/dot-placeholders.ts), like [PLACEHOLDER; never use them as filler.
- About page (/about/): Nani's namaste picture (ward.json → `overviewImage`, from raw-data Naninamaste.jpeg) sits beside the Overview text, raised towards the heading, from 768 px; below the text on phones.
- About page: the ward illustration (content/ward.json → `illustration`, built from raw-data wardlogo1.png by optimize-images) sits beside the About Ward No. 16 text from 768 px, below it on phones.
- The floating 3D Map button is a small red circle (size-12) with the word "Map"/"नक्सा" (map.floatingButtonShort), as far from the edges as Nani's face; its accessible name and tooltip are map.floatingButton ("3D Map").
- About page: the complete ward profile map (ward.json → `wardMap`, raw-data "ward 16.jpg", manifest `wardMap`) sits under the Overview text, in the text column; it links to its largest file. Beside it, under Nani's namaste in the image column, is the ward logo (ward.json → `overviewLogo`, the round wardlogo.png files).
- Header: the whole brand (logo + title lines) is one link home (BrandLink.tsx), named a11y.homeLink ("Ward No. 16, home"); on the home page it scrolls to the top (instant under reduced motion).
- Sticky nav: once the header has scrolled out of view, the small round ward logo (ward.json → `logo`) slides in at the left of the red bar as a home link (BrandLink, same name and scroll-to-top); while hidden it is `inert`. The footer brand (logo + name + city) is the same kind of home link.
- Photos beside list items on a heritage page (e.g. Nanak Math's "यहाँ भएका सम्पदाहरू" / "The Heritage Here") are set in content/section-photos.json (site → section id → item number → gallery photo, or `{ "photo", "description": false }`) and placed by src/lib/rehype-section-photos.ts: text left, photo right from 768 px, text then photo on phones; the photo's gallery description is shown under the item's title unless switched off; "removed" photos are skipped; an unknown photo or item number fails the build.
- Detail pages render optional parts only when there is data: map button needs coordinates, "Other heritage" needs another visible site, quick facts skip empty fields, the photo credit needs `photos.team` in content/credits.json.
- Photos showing identifiable people are listed in content/photo-consent.json (pending/approved/removed) and docs/photos-with-people.md; "removed" hides a photo everywhere. Check every newly added photo for faces.
- Published images must carry no metadata; verify-output fails on EXIF/XMP/text chunks. Only add images through `npm run optimize-images`.
- Map (src/components/MapView.tsx): never start camera animations before the first "idle" after terrain loads (the camera ends up inside the terrain and the map goes blank), and never bind popups with marker.setPopup() (MapLibre closes them when its terrain-occlusion test misfires). On mobile screens (under 1024 px: `MOBILE_QUERY` in src/lib/breakpoints.ts, the one breakpoint for all map layout and loading decisions) a direct visit shows the still map/preview picture and a "Show 3D map" button; arriving from any page of the site (client navigation or same-origin referrer) loads the map at once (MapExplorer.tsx). Retake the preview (from a build:preview, no drafts) when the places change.
- No external map links (OpenStreetMap, Google Maps or others) anywhere on the site: addresses are plain text plus our own "View on 3D Map" link. The 3D map keeps its attribution line (OpenFreeMap, OpenMapTiles, OpenStreetMap, terrain).
- The museum is the frame of every page (MuseumShell.tsx, mounted once in src/app/[lang]/layout.tsx with data from src/lib/museum-shell.ts): one canvas and WebGL renderer for the whole visit, camera and state kept across pages. Home (Overview) = the museum itself (page.tsx renders nothing). Every other page lives in the route group `src/app/[lang]/(site)/` (no URL segment) and opens as an information panel floating over the museum (about 62% of the width on desktop, nearly full width on phones; cream, gold border); the museum stays visible around it, still and taking no input (phase "backdrop"). The panel scrolls inside itself; × / Esc / a click beside it closes it (client navigation home: the scene and camera are untouched). Page content is unchanged but lays itself out for the panel's width: use container-query variants (`@xl:` `@2xl:` `@4xl:`) instead of `sm:` `md:` `lg:` in page components. No site header or footer anywhere (Header/Footer/Nav components are kept but unused). The /gallery/ page passes `museum={false}` to Gallery: no second 3D museum; its hanging and list views remain. Control row (MuseumTopBar.tsx), fixed on every page: the Ward No. 16 emblem (ward.json → `logo`, home link) top left, then About / Heritages / Gallery (open their panels) and Contact (popup, native <dialog>); below 60rem these fold into a dropdown named after the current page, and the RatnaInTech logo (public/images/logo/Ratna.png, transparent; no backing) beside the language toggle.
- Pages: the menu items are pages of their own (getNavItems in src/lib/i18n.ts): Overview = the home page (the museum, and nothing else), About = /about/ (About Ward No. 16 + Overview sections), Heritages = /heritages/ (site cards), Gallery = /gallery/, Contact = /contact/. No home-page anchors: chatbot links use these paths.
- Home page opens inside the online museum (MuseumLanding.tsx, 21 Nov 2026; replaces the hero slideshow and the old museum section). Crimson "Read About →" plaques (home.museumReadAbout) hang under each signboard (to that site's page) and to the left of the emblem (to /about/); each has a keyboard link named home.museumReadAboutLabel. It is the gallery's 3D museum (src/components/gallery/) in its exhibit layout (src/lib/museum-world.ts): an entrance hall with the ward map (left wall, ward.json → `wardMap`) and the ward logo (right wall, `overviewLogo`), then a junction whose far wall has brass signboards (home.museumSigns: Nanak Math ← left — "Living Bhu-Samadhi Site of Mahayogi Shri Brahmaharidas Maharaj" with "Prachin Udashin Nanak matha" on a second, smaller line (a "
" in the string; long parts wrap on the sign) — "Mhepi Ajima" → right; sides in page.tsx `WING_SIDE`) leading into one wing per visible site. A red carpet runs down every hall (also on /gallery). Intro: title (home.museumLandingTitle) and "Start Exploring" over a slow forward walk (30 fps, only while on screen, still under reduced motion); afterwards arrow keys walk/turn, wheel walks, drag looks, touch buttons on phones. Clicking any picture (here and on /gallery) flies the camera up to it and shows its existing caption/site/credit in a card (no PhotoView, which stays for the hanging and list views); the logo card has "About Ward 16 →" to /about/. Wing photos load only when that wing is approached. Without WebGL, Start Exploring shows the hanging gallery. Wording of the five landing labels is fixed by the ward team: do not change it.
- Gallery panel typography: Alegreya Sans (filters 16px/600 — the font has no 600, so it renders 700 — second line 14px/500, captions 400–500) and Alegreya 700 for headings, via next/font in src/app/fonts.ts (self-hosted, not preloaded; Nepali falls back to Mukta). No uppercase or letter-spacing on gallery labels. The Nanak Math filter's second line is `gallery.siteSubtitles` ("Prachin Udaseen Nanak Math", Roman script, the same in EN and NE). PhotoView renders through a portal to <body> (the panel's container queries would otherwise contain it).
- Museum exhibits (src/lib/museum-layout.ts → MUSEUM): large prints (2.6 m tall, own aspect ratio, never cropped) all standing on one base line (`frameBaseY`), each with its existing alt text on a cream label right underneath at a fixed type size (`descriptionFont`); a longer description makes the label taller, not the type smaller. A close look frames picture and label together; the photo card links to its site's page ("Read more").
- content/home.json → `heroSlides` is now only the default share image (layout.tsx): keep `carved-windows` and photos dominated by faces out of it.
- Links to the home page use prefetch={false}, so other pages do not preload the home page.
- Pin new npm packages to a release at least two weeks old (--save-exact).
- Chatbot: tap-only (topic → question → answer), no typing and no search library. Topics and answers live only in content/faq.json (EN + NE). Topics are generated: "Visiting {site}" and "About {site}" per visible site (`topic: "visit" | "about"` + `site`), then the fixed topics; `site` drops a draft site's answers; `topic: null` = related-only. `priority` orders questions within a topic; `suggestions` are the opening quick questions; `directions: true` adds a "View on 3D Map" link for the site (with the approximate note when flagged). Questions are short and plain ("How do I get there?"). Never add a name or fact without a source (e.g. "Siddheshwar Mahadev" is waiting for one). Answers may use {sites} {address} {phone} {email} {team}; links are language-less paths whose #anchors are checked at build. Every option is a real <button>, with "My question isn't here" last in every list (its reply links the ward phone and email, then offers only "← Back to topics"). The chat must make no network requests: no prefetch on its links.
- Justified text: only running paragraphs (`.justified`, `.heritage-prose > p`, `.heritage-prose .item-desc`, `.map-detail-prose > p`), last line left, English `hyphens: auto`. Justified only from 1024 px (lg); phones and tablets stay left-aligned. The heritage list descriptions (`.item-desc`, beside photos) wait until 1280 px (xl) in their own block. The one switch is the `@media` line under "ONE SETTING" in globals.css: `(width >= 64rem)` (chosen), `all` = justified everywhere.
- useEffect bodies must be blocks, never `() => el.method()`: some browsers return Promises from DOM methods (e.g. scrollIntoView) and React then crashes.
- Floating buttons: Nani/chatbot bottom-RIGHT, 3D Map bottom-LEFT (swapped from the sketch on 14 Nov 2026). Side offsets are `max(gap, env(safe-area-inset-…))`; the chat panel opens above Nani, growing up and to the left.
- Nani (chatbot guide): the floating button is the 56 px round face on every page; only hovering over it with a mouse shows the big half-body cut-out (nani-figure-\*.webp, 130 px below md / 260 px from md, gentle CSS sway, off under reduced motion) and her speech bubble (not while the chat is open). Touch screens never show or download the big figure; the chat header and message avatars use the round face via <NaniAvatar>. All are built by optimize-images. Avatars beside messages are static with alt="" (the sr-only "Nani:" prefix names her).
- Contact: no form and no form service (Web3Forms removed 17 Nov 2026). /contact/ shows a welcoming message and the ward office email as a mailto: link (with a subject), plus the office details; strings under `contactPage` in src/i18n/\*.json.
- Ward details (address, phone, email, logo) live in content/ward.json — never hard-code them in components.
- Raw data is in ward16-heritageraw-data/HOC/ (git-ignored, ~1.5 GB). Web images are built from it by `npm run optimize-images` using scripts/image-manifest.json (480/640/960/1280/1920 px; `fullBleed` photos get stronger compression); alt text lives in content frontmatter.
- Bilingual EN/NE via app/[lang]/. UI strings in src/i18n/. Font: Mukta for Devanagari.
- Strict TypeScript, no `any`. Client components only where needed (map, chatbot, gallery, nav toggle).
- Team knows JS/TS, React, Next.js, PostgreSQL — explain anything new (MapLibre, Fuse.js) in comments.
- Mobile-first, accessible, every image has alt text.
- Work one phase of PLAN.md at a time; commit and stop for review after each.
- Walking route: content/routes.json lists stops (heritage slugs, in order). Unpublished (draft) stops are dropped in src/lib/map-data.ts, and a route with fewer than two published stops is not shown at all. Without a `walking` block the map draws a dashed straight line and shows straight-line distances only, labelled as such; never type walking distances or times by hand, run `npm run fetch-route` instead.
- Map state lives in src/components/MapExplorer.tsx (selection, search, filters, route step); MapView.tsx only draws it. Map UI strings live under `map` in src/i18n/\*.json; Nepali strings there need a native-speaker check.

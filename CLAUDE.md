# Ward 16 Heritage Website
- Sites: Mhepi Ajima, Nanak Math — Ward No. 16, Kathmandu Metropolitan City
- Stack: Next.js (App Router) + TypeScript + Tailwind, static export (output: 'export'). Hosting: Cloudflare Pages.
- No server features: no API routes, server actions, middleware or ISR.
- Everything must be FREE. No paid services, no API keys needing billing.
- Theme: red. Use only the named Tailwind colors: crimson, brick, vermilion, gold, cream, sand, ink. Vermilion and gold fail AA for body text — decoration / large text only (see src/app/globals.css).
- Layout follows raw-data/sketch.jpg (actual file: ward16-heritageraw-data/HOC/sketch.png).
- Content lives ONLY in content/. Never invent historical facts; use [TODO: …] and log in MISSING_INFO.md.
- Draft content: files with `draft: true` may hold [PLACEHOLDER: …] text. `npm run check-content` (run automatically by `npm run build`) fails on any [PLACEHOLDER, [TODO or draft — never bypass it. In dev, draft pages show <DraftBanner>.
- `npm run build:preview` builds without draft sites. Every page, link, gallery, map marker and chatbot answer must get sites from `getHeritageList()` / `getHeritageSlugs()` (src/lib/content.ts); scripts/verify-output.ts (after both builds) fails if a draft slug or name, or any [PLACEHOLDER/[TODO text, appears anywhere in out/.
- Every h2/h3 in content needs a stable English id, same in EN and NE: `## इतिहास {#history}` (enforced by check-content and the remark plugin).
- Client components import Locale/LOCALES from @/types/locale, never @/types/heritage (that pulls zod and site slugs into the browser bundle).
- Cite sources in content with `<!-- source: key1, key2 | reviewer detail -->`; keys and their plain-language names live in content/sources.json and feed each page’s Sources section (an unknown key fails the build).
- Detail pages render optional parts only when there is data: map button needs coordinates, "Other heritage" needs another visible site, quick facts skip empty fields, the photo credit needs `photos.team` in content/credits.json.
- Photos showing identifiable people are listed in content/photo-consent.json (pending/approved/removed) and docs/photos-with-people.md; "removed" hides a photo everywhere. Check every newly added photo for faces.
- Published images must carry no metadata; verify-output fails on EXIF/XMP/text chunks. Only add images through `npm run optimize-images`.
- Map (src/components/MapView.tsx): never start camera animations before the first "idle" after terrain loads (the camera ends up inside the terrain and the map goes blank), and never bind popups with marker.setPopup() (MapLibre closes them when its terrain-occlusion test misfires). On phones (<768 px) a direct visit shows the still map/preview picture and a "Show 3D map" button; arriving from any page of the site (client navigation or same-origin referrer) loads the map at once (MapExplorer.tsx). Retake the preview (from a build:preview, no drafts) when the places change.
- Links to the home page use prefetch={false}, so other pages do not preload the home hero image.
- Pin new npm packages to a release at least two weeks old (--save-exact).
- Chatbot: tap-only (topic → question → answer), no typing and no search library. Topics and answers live only in content/faq.json (EN + NE). Topics are generated: "Visiting {site}" and "About {site}" per visible site (`topic: "visit" | "about"` + `site`), then the fixed topics; `site` drops a draft site's answers; `topic: null` = related-only. `priority` orders questions within a topic; `suggestions` are the opening quick questions; `directions: true` adds the 3D-map and OpenStreetMap links from the site's coordinates (with the approximate note when flagged). Questions are short and plain ("How do I get there?"). Never add a name or fact without a source (e.g. "Siddheshwar Mahadev" is waiting for one). Answers may use {sites} {address} {phone} {email} {team}; links are language-less paths whose #anchors are checked at build. Every option is a real <button>, with "My question isn't here" last in every list (its reply links the ward phone and email, then offers only "← Back to topics"). The chat must make no network requests: no prefetch on its links.
- useEffect bodies must be blocks, never `() => el.method()`: some browsers return Promises from DOM methods (e.g. scrollIntoView) and React then crashes.
- Nani (chatbot guide): the floating button is the 56 px round face on every page; only hovering over it with a mouse shows the big half-body cut-out (nani-figure-*.webp, 130 px below md / 260 px from md, gentle CSS sway, off under reduced motion) and her speech bubble (not while the chat is open). Touch screens never show or download the big figure; the chat header and message avatars use the round face via <NaniAvatar>. All are built by optimize-images. Avatars beside messages are static with alt="" (the sr-only "Nani:" prefix names her).
- Ward details (address, phone, email, logo) live in content/ward.json — never hard-code them in components.
- Raw data is in ward16-heritageraw-data/HOC/ (git-ignored, ~1.5 GB). Web images are built from it by `npm run optimize-images` using scripts/image-manifest.json (480/640/960/1280/1920 px; `fullBleed` photos get stronger compression); alt text lives in content frontmatter.
- Bilingual EN/NE via app/[lang]/. UI strings in src/i18n/. Font: Mukta for Devanagari.
- Strict TypeScript, no `any`. Client components only where needed (map, chatbot, gallery, nav toggle).
- Team knows JS/TS, React, Next.js, PostgreSQL — explain anything new (MapLibre, Fuse.js) in comments.
- Mobile-first, accessible, every image has alt text.
- Work one phase of PLAN.md at a time; commit and stop for review after each.
- Walking route: content/routes.json lists stops (heritage slugs, in order). Unpublished (draft) stops are dropped in src/lib/map-data.ts, and a route with fewer than two published stops is not shown at all. Without a `walking` block the map draws a dashed straight line and shows straight-line distances only, labelled as such; never type walking distances or times by hand, run `npm run fetch-route` instead.
- Map state lives in src/components/MapExplorer.tsx (selection, search, filters, route step); MapView.tsx only draws it. Map UI strings live under `map` in src/i18n/*.json; Nepali strings there need a native-speaker check.
